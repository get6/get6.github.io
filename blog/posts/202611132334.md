만들고 싶은 아이디어는 메모장에 쌓이는데, 실제로 만들어지는 건 몇 개 안 되죠. 이 글은 **AI 에이전트 워크플로우**로 아이디어 노트 한 장을 에이전트가 끝낼 수 있는 이슈로 쪼개고, 하나씩 맡겨 검증까지 끝내는 방법을 정리했어요. 예시 아이디어 노트, 쪼개기 지시문, 완성된 이슈 모양까지 그대로 따라 쓸 수 있게 담았어요.

예전에는 기획 에이전트, 개발 에이전트처럼 역할을 나눈 조직도를 짜고, 폴더를 감시하는 파이프라인을 만들려고 했어요. 그 설계는 실제로 돌아가지 않았어요. 이유는 [AI 에이전트 자동화 사례 4가지, 대화 대신 목표 맡기기](/posts/202611022014)에 정리해뒀어요. 이 글은 그 뒤에 바꾼 방식이에요.

## 역할 조직도 대신 네 단계 흐름으로 봐요

에이전트에게 직함을 붙이는 것보다 중요한 건, **일이 어떤 문서를 거쳐 끝나는지**예요. 흐름은 네 단계면 충분해요.

| 단계            | 누가                   | 남는 것               |
| --------------- | ---------------------- | --------------------- |
| **1. 아이디어** | 나                     | 아이디어 노트 한 장   |
| **2. 쪼개기**   | 나 + 에이전트 (대화)   | 완료 조건이 있는 이슈 |
| **3. 실행**     | 에이전트 (이슈 하나씩) | 브랜치와 PR           |
| **4. 검증**     | 테스트 + 나            | 머지된 코드           |

사람이 맡는 건 **무엇을 왜 만들지 정하는 일과 끝났는지 확인하는 일**이에요. 쪼개기 초안과 구현은 에이전트가 맡아요. 기억은 대화가 아니라 노트, 이슈, git에 남겨요.

## 1단계: 아이디어 노트에는 "왜"와 "하지 않을 것"을 적어요

아이디어 노트는 짧아도 돼요. 다만 세 가지는 꼭 들어가야 해요. 예를 들어 앱에 소셜 로그인을 붙이고 싶다면 이렇게 써요.

```markdown
# 소셜 로그인 도입

## 원하는 것

카카오, 애플 로그인을 앱에 붙이고 싶다.

## 왜

유저들이 더 편하게 가입할 수 있으면 좋겠다.

## 하지 않을 것

- 이번에는 기존 이메일 계정과 소셜 계정을 합치지 않는다
- 구글 로그인은 다음에 한다
```

1. **원하는 것** — 무엇을 만들지 한두 문장이에요.
2. **왜** — 에이전트가 애매한 지점에서 판단할 기준이 돼요. 이게 없으면 에이전트는 가장 그럴듯한 쪽으로 추측해요.
3. **하지 않을 것** — 범위를 잘라줘요. 에이전트는 시키지 않은 일까지 친절하게 해버리는 경우가 많거든요.

어떻게 만들지는 쓰지 않아도 돼요. 그건 다음 단계에서 에이전트와 같이 정해요.

## 2단계: AI 에이전트와 대화하며 이슈로 쪼개기

쪼개기는 자동으로 돌리기보다 **대화로 하는 게** 잘 맞아요. 아이디어를 어떤 단위로 나눌지는 판단이 많이 필요한 일이라, 에이전트가 초안을 내고 사람이 바로 고치는 편이 빠르거든요. 지속적으로 도는 자동화 루프에서도 스펙만큼은 대화로 먼저 만들어두는 경우가 많아요.

Claude Code나 Codex 같은 코딩 에이전트에게 아이디어 노트와 함께 이런 지시문을 줘요.

```markdown
첨부한 아이디어 노트를 이슈 초안으로 쪼개줘.

- 이슈 하나는 PR 하나로 끝나는 크기로 나눈다.
- 이슈마다 목표, 맥락, 완료 조건, 검증 방법, 하지 말 것을 쓴다.
- 완료 조건은 "된다/안 된다"로 확인할 수 있는 문장으로 쓴다.
- 완료 조건을 쓸 수 없으면 더 잘게 쪼갠다.
- 맥락에는 원래 아이디어 노트 링크를 넣는다.
- 아직 이슈를 만들지 말고, 초안만 보여준다.
```

마지막 줄이 중요해요. 초안을 읽고 고치는 이 순간이 **사람이 개입하는 가장 값싼 지점**이에요. 여기서 애매한 이슈를 걸러내면, 나중에 결과물을 붙잡고 고치는 시간이 크게 줄어들어요.

### 완료 조건이 있는 이슈는 이렇게 생겨요

위 아이디어라면 화면 작업과 서버 작업으로 나뉘겠죠. 화면 쪽 이슈는 이런 모양이 돼요.

```markdown
# 카카오 로그인 UI 구현

## 목표

로그인 화면에서 카카오 계정으로 로그인을 시작할 수 있게 한다.

## 맥락

- 아이디어 노트: ideas/소셜로그인-도입.md
- 서버 연동은 별도 이슈에서 한다

## 완료 조건

- 로그인 화면에 카카오 로그인 버튼이 보인다
- 버튼을 누르면 카카오 인증 화면으로 넘어간다

## 검증 방법

- 로그인 화면 테스트를 추가하고 통과시킨다
- 실행 화면 스크린샷을 PR에 첨부한다

## 하지 말 것

- 기존 이메일 로그인 화면의 레이아웃은 바꾸지 않는다
```

이슈 본문 구조는 [Obsidian 노트를 AI 에이전트 작업 지시서로 쓰기](/posts/202610012001)에서 쓰던 목표, 맥락, 완료 조건, 하지 말 것 구조에 **검증 방법**을 더한 거예요. 맥락에 아이디어 노트 링크를 남겨두면, 이슈가 몇 개로 나뉘어도 어느 아이디어에서 나왔는지 거꾸로 따라갈 수 있어요.

### 맡기기 전에 확인할 것

- [ ] 완료 조건이 확인 가능한 문장인가?
- [ ] PR 하나로 끝나는 크기인가?
- [ ] 맡긴 뒤에 덧붙여야 할 말이 남아 있지 않은가?

세 번째가 의외로 중요해요. GitHub Copilot은 이슈를 할당받은 뒤에 달린 댓글을 보지 못한다고 공식 문서에 적혀 있어요. 하고 싶은 말은 **맡기기 전에 이슈 본문에 다 적어야** 해요.

## 3단계: 이슈를 하나씩 에이전트에게 맡기기

이슈가 준비되면 실행은 이미 쓰고 있는 도구 위에서 하면 돼요. 폴더 감시기나 할당 엔진을 새로 만들 필요가 없어요.

- **GitHub 이슈** — 이슈 담당자(Assignees)에 Copilot을 지정하거나, 이슈 댓글에서 `@claude`를 멘션하면 에이전트가 브랜치를 만들어 작업하고 PR로 돌려줘요.
- **이슈 트래커형 도구** — [Multica](https://multica.ai/docs/autopilots) 같은 도구에서는 이슈를 에이전트에게 할당해 실행해요.
- **내 컴퓨터에서 직접** — 코딩 에이전트에게 이슈 본문을 그대로 주고 실행해요.

어느 쪽이든 원칙은 같아요. **한 번에 이슈 하나만** 맡겨요. 한 번에 많이 시키면 에이전트가 중간에 컨텍스트가 바닥나서, 반쯤 만든 채로 끝나기 쉬워요.

여러 이슈를 내 컴퓨터에서 동시에 돌리고 싶다면 **Git 워크트리**(Git Worktree)를 써요. 워크트리는 같은 저장소를 브랜치별로 다른 폴더에 꺼내 쓰는 Git 기능이에요. 에이전트마다 폴더가 따로 있으니 서로의 파일을 덮어쓰지 않아요.

## 4단계: 끝났는지는 에이전트 말이 아니라 검증으로 판단해요

에이전트가 "다 했어요"라고 해도 그대로 믿으면 안 돼요. 이슈에 적어둔 **검증 방법**이 판단 기준이에요.

1. **자동 검증** — 테스트, 정적 분석, 타입 체크가 잘못된 결과를 먼저 튕겨내요. CI에 걸어두면 PR마다 저절로 돌아요.
2. **사람 리뷰** — PR에서 완료 조건을 하나씩 대조하고, 스크린샷이나 실행 결과를 확인한 뒤 머지해요.
3. **같은 실수가 반복되면 지시 파일을 고쳐요** — 저장소의 `CLAUDE.md` 같은 규칙 파일에 한 줄을 더하면, 다음 이슈부터는 같은 실수를 덜 해요.

이슈가 모두 머지되면 아이디어 노트에 "완료"와 PR 링크를 남겨요. 그러면 아이디어 노트 하나가 **무엇을 왜 만들었고, 어디서 확인할 수 있는지**까지 담은 기록이 돼요.

## 자동화는 반복되는 일에만 나중에 붙여요

처음부터 아이디어를 넣으면 알아서 도는 파이프라인을 만들고 싶어지죠. 하지만 자동화 도구 자체를 관리하는 비용이 생각보다 커요. 이 순서로 작게 시작해보세요.

1. 아이디어 노트 하나를 위 형식으로 써요.
2. 에이전트와 대화하며 이슈 초안을 받고, 직접 읽고 고쳐요.
3. 이슈 하나를 에이전트에게 맡기고, 검증 방법대로 확인한 뒤 머지해요.
4. 같은 종류의 일이 계속 반복될 때만, 예약 실행이나 Multica 오토파일럿(Autopilots) 같은 기능으로 그 일을 자동화해요.

## 아이디어를 끝까지 만드는 건 자동화의 양이 아니에요

아이디어가 실제 결과물로 이어지게 하는 건 거창한 에이전트 조직이 아니었어요. **완료 조건이 적힌 이슈**와 **검증으로 끝을 판단하는 습관**이었어요. 이 두 가지가 있으면 혼자서도, 에이전트 하나로도 아이디어가 코드까지 이어져요.

머릿속에만 있던 아이디어 하나를 오늘 노트로 적고, 에이전트에게 이슈 초안을 받아보는 것부터 시작해보세요.
